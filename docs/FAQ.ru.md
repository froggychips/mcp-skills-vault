# mcp-skills-vault — FAQ

Быстрые ответы для пользователей Claude Code, которым интересно — зачем это ставить.

---

## Что это такое?

База данных из 112 MCP-серверов (94 проверены вручную + 18 кандидатов), сканер безопасности цепочки поставок и CLI, который связывает всё вместе.

Когда хочешь добавить MCP-сервер в проект, это даёт:
- Курированный список надёжных серверов с оценкой качества (не 1000+ записей из официального реестра)
- Проверку хэша перед тем как что-то запишется в конфиг
- Одну команду, которая определяет что скорее всего нужно именно твоему проекту

---

## Зачем, если я могу поставить MCP-серверы сам?

Можешь. Но есть две проблемы:

**Нет сигнала качества.** Официальный реестр MCP перечисляет всё подряд. Этот проект — только то, что стоит использовать: 112 записей, каждая оценена по свежести, звёздам, лицензии и тому, работает ли установка вообще.

**Цена в токенах.** Каждый активный MCP-сервер вставляет весь список своих инструментов в контекст Claude. У некоторых серверов 100+ инструментов — это тысячи токенов на каждое сообщение, даже если ты эти инструменты не используешь. В базе есть поле `est_tools_count` для каждой записи, чтобы принимать осознанные решения перед установкой.

---

## Что на самом деле проверяет хэш?

Для npm: заново скачивает `dist.integrity` из реестра для закреплённой версии и сравнивает байт в байт с сохранённым хэшем.  
Для PyPI: sha256 архива sdist.  
Для Docker: образ должен быть закреплён через `@sha256:<digest>`.

Если хэш не совпадает — установка блокируется. Если есть известная уязвимость — флагуется через OSV.dev / npm advisory API.

**Важная оговорка:** совпадение хэша означает что артефакт идентичен опубликованному в той версии. Это не означает что код безопасен — только что он не был изменён с момента записи хэша.

---

## Что значит Core / Recommended / Experimental?

Серверы оцениваются по формуле:

```
score = min(20, 10·log10(stars+1))   # популярность, с потолком
      + {40|20|10|0}                  # свежесть: <30д / <90д / <180д / старше
      + 30 если есть в публичном реестре
      + 15 если задокументирована команда установки
      − 10 если лицензия не OSI или неизвестна
```

| Уровень | Оценка | Поведение |
|---|---|---|
| Core | 85+ | Рекомендуется по умолчанию |
| Recommended | 65–84 | Рекомендуется с пометкой |
| Experimental | 40–64 | Упоминается только по запросу |
| Deprecated | < 40 | Скрыт, если не спрашивать |

## Как пользоваться?

```bash
# Что нужно этому проекту?
npx -y @froggychips/mcp-vault scan --cwd /path/to/project

# Поиск по ключевому слову
mcp-vault scan --query kubernetes

# Установка — проверяет хэш, пишет .mcp.json
mcp-vault install github-mcp-server
```

Или положи папку скилла в `~/.claude/skills/mcp-ecosystem-intelligence/` и спроси Клода как обычно: *"Какие MCP-инструменты поставить для этого Next.js проекта?"*

## Читает ли .env значения?

Только имена ключей. Сканер использует регулярку `/^([A-Z0-9_]+)=/` — читает `GITHUB_TOKEN=` и останавливается на `=`. Значения никогда не захватываются, не сохраняются и не выводятся. Если найдёшь код где значение утекает — это баг безопасности, стоит сообщить.

---

## Куда `--install` записывает конфиг?

По умолчанию: `.mcp.json` в корне проекта (project-scoped). Сервер активен только в этом проекте, невидим везде остальном.

Для глобальной установки (кросс-проектные инструменты типа `mcp-server-memory`):
```bash
mcp-vault install mcp-server-memory --global
```

Глобальные установки идут в `~/.claude.json`.

## Как база данных остаётся актуальной?

Workflow GitHub Actions запускается каждый понедельник:
1. Перезапрашивает хэши из npm/PyPI для всех 112 записей
2. Обновляет метрики GitHub (звёзды, дата последнего коммита, открытые issues)
3. Открывает PR — **нужна проверка человеком перед слиянием**

PR — единственный автоматический путь изменить `tools_database.json`. Апгрейды версий никогда не мёрджатся автоматически. Ревьюеры проверяют необъяснённые прыжки мажорных версий, которые могут указывать на скомпрометированный релиз.

---

## Чем это отличается от официального реестра MCP?

Официальный реестр перечисляет что существует (~1000+ записей). Этот проект перечисляет что стоит использовать (112 записей), проверяет хэш и оценивает по здоровью. Это кюрированный шортлист, не директория.

---

## Можно предложить новый сервер?

Открой issue. Для добавления нужно: закреплённая версия, хэш из публичного реестра, рабочая команда установки и оценка выше 40.

---

## Это что-то куда-то отправляет?

Никакой телеметрии. Проверщик хэшей обращается к публичным API (реестр npm, PyPI, OSV.dev) — эти запросы раскрывают имя пакета и версию, так же как `npm install` напрямую.
